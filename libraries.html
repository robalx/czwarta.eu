Biblioteki i narzędzia dla programistów

Python, JavaScript/Node, Go, Infra/DevOps - bloki kodu z kopiowaniem oraz interaktywny builder komend ffmpeg.

Narzędzia deweloperskie do monitoringu dzielą się na cztery rodziny: przetwarzanie obrazu (Python), strumieniowanie webowe (Node.js), wydajne proxy RTSP (Go) oraz infrastrukturę kontenerową i transkodującą (DevOps). Poniżej konkretne biblioteki i działające snippety - z kopiowaniem.

Python #

Python to naturalny wybór do analizy obrazu i szybkich narzędzi wewnętrznych. Poniżej minimalny przykład użycia OpenCV do pobrania pojedynczej klatki ze strumienia RTSP - klasyczny punkt startowy każdego skryptu monitoringu.

python
import cv2

cap = cv2.VideoCapture("rtsp://user:pass@192.168.1.10:554/stream1")
ret, frame = cap.read()

if ret:
    cv2.imwrite("klatka.jpg", frame)
    # dalej: analiza przez YOLO, wysłanie do S3, powiadomienie itp.

cap.release()

Ten sam kawałek można owinąć w endpoint FastAPI, by mieć REST-owy snapshot pod adresem /snapshot:

python
from fastapi import FastAPI
from fastapi.responses import Response
import cv2

app = FastAPI()

@app.get("/snapshot")
def snapshot():
    cap = cv2.VideoCapture("rtsp://user:pass@192.168.1.10:554/stream1")
    ret, frame = cap.read(); cap.release()
    if not ret:
        return Response(status_code=503)
    ok, buf = cv2.imencode(".jpg", frame)
    return Response(buf.tobytes(), media_type="image/jpeg")

Przydatne biblioteki ekosystemu:

  • opencv-python - przetwarzanie obrazu i video, capture z RTSP/RTMP
  • onvif-zeep - komunikacja ONVIF (discover, PTZ, zdarzenia)
  • imutils - ułatwienia i convenience dla OpenCV
  • flask / fastapi - wystawienie własnego serwera WWW / API
  • ultralytics - YOLOv8 do detekcji obiektów na klatkach
W produkcji

Dodaj obsługę wyjątków (timeout, reconnect), uruchom w kontenerze Docker i loguj zdarzenia. cv2.VideoCapture potrafi zawiesić się na niedostępnym strumieniu - ustaw os.environ['OPENCV_FFMPEG_CAPTURE_OPTIONS']='rtsp_transport;tcp' i timeout.

JavaScript / Node.js #

Node.js świetnie nadaje się do warstwy webowej: re-streaming RTSP do WebSocketów, transkodowanie przez ffmpeg i komunikacja IoT przez MQTT.

javascript
const Stream = require("node-rtsp-stream");

const stream = new Stream(
  streamUrl: "rtsp://user:pass@192.168.1.10:554/stream1",
  wsPort: 9999,
  ffmpegOptions: 
    "-stats": "",
    "-r": 30
);
// klient webowy:  ws://localhost:9999  ->  canvas/MJPEG

Uwaga: powyższy snippet jest skrócony dla czytelności - w kodzie obiekt konfiguracyjny otocz nawiasami klamrowymi. Kluczowe pakiety to node-rtsp-stream (strumień do WebSocket), ffmpeg-static (binarka ffmpeg bez instalacji) oraz mqtt (komunikacja z brokerem IoT).

Go #

Go to świetny wybór na lekki serwer proxy strumieni - statycznie linkowana binarka, niskie zużycie pamięci, natywna współbieżność. Biblioteka gortsplib implementuje pełnego klienta i serwer RTSP.

go
package main

import (
    "github.com/bluenviron/gortsplib/v4"
)

func main()
    c := &gortsplib.Client
    err := c.Start("rtsp://192.168.1.10:554/stream1")
    if err != nil  panic(err) 
    // czytaj ramki H264, re-streamuj, transkoduj...

W realnym kodzie pamiętaj o poprawnych nawiasach klamrowych dla bloków funkcji i struct - powyższy listing jest skrócony. gortsplib pozwala budować własne serwery proxy RTSP, transkodować strumienie i mostkować RTSP ↔ WebRTC.

Infra / DevOps #

Warstwa infrastruktury utrzymuje wszystko w ruchu: transkodowanie, konteneryzację, serwer streamingowy i monitoring metryk.

  • ffmpeg - transkodowanie, zrzuty klatek, segmentacja HLS
  • docker + compose - izolacja usług, reprodukowalne wdrożenia
  • nginx + rtmp-module - serwer strumieni RTMP/HLS
  • prometheus + grafana - monitoring metryk (fps, dropped frames, latency)

# docker-compose.yml - Frigate + Coral

    restart: unless-stopped
